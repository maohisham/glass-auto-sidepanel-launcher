# Tidy-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 18 items in the spec without changing how any feature looks or works, apart from where the summary card sits.

**Architecture:** Pure rules get JUnit tests: the share-link parsing, the shuffle retry, the "once at a time" gate, and the fuel-price date and timing. The rest is small, local wiring in the existing Android classes.

**Tech Stack:** Android Java, JUnit 4. Run from the repo root:

**Spec:** `docs/superpowers/specs/2026-11-15-tidy-up-design.md`

## Global Constraints

- No visible change to any feature except the summary card's position (item 11).
- Every decision is logged with `Spike.log`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A shared YouTube Music `watch?v=…&list=RD…` "mix" link:** it's accepted as a playlist link (`playlist?list=RD…`), and the video id is dropped.
2. **Sun switching while the picker is open:** the picker is rebuilt in the new colours and stays open. A search in progress may be lost; that's acceptable.
3. **The card over the lyrics area, before the panel has laid out (height 0):** it falls back to the top of the panel and never covers the controls.
4. **An unparseable or missing price date:** the 7-day rule from the last successful fetch applies.
5. **Settings rebuilt with a fold open:** the fold is still open, and the page is scrolled to the same place.

**Interfaces:**
- **`ShareLink.parse`** accepts `http://` (normalised to `https://`) and YouTube Music `watch?…list=…`. It accepts `browse/VL…` and `browse/MPRE…`, and refuses other `browse/` ids.
- **`ShareLink.firstLink(String text) -> String`:** the first link in the text, for the log, or `""`.
- **`ShuffleMemory.retry(int current, boolean available, int attempt) -> boolean`:** `attempt < 3 && (current < 0 || !available)`.
- **`PlayerPicker.handleBack()`** also closes the pin menu, going back to the main view. **`PlayerPicker.refresh()`** redraws the main view when it's showing.
- **`PanelActivity.onBackPressed`** closes the pin choice overlay first. The overlay is held in a field.

### Task 5: Fuel price and beep (items 15–18)

**Files:**
- Modify: `FuelPrice.java`, `Settings.java` (save and read `fuelPriceDate` as a `"yyyy-MM-dd"` string), `PanelActivity.java`, `SpeedAlert.java`
- Test: `FuelPriceTest.java` (add)

**Interfaces:**
- **`FuelPrice.Result parseFull(String json)`:** `{budi95, ron95, date}`, or null. `parse` stays, as a call to it.
- **`FuelPrice.due(long lastFetchMs, String priceDate, long now) -> boolean`:**
  - never fetched → true;
  - a parseable `priceDate` → `now >= start of (priceDate + 7 days)`, local time, and `now - lastFetchMs >= 6 h`;
  - no parseable date → the old 7-day rule.
- **`FuelPrice.mayTry(long lastAttemptMs, long now) -> boolean`:** at most once an hour. `PanelActivity` keeps `lastAttemptMs` in a static field.
- **The log line** adds `(prices from <date>)`.
- **`SpeedAlert.putBack`:** in its catch, tries `setStreamVolume(STREAM_MUSIC, before, 0)` once, and logs it.

**Steps:**

- [ ] **Step 1: Write the failing tests.** Use `TimeZone.setDefault(TimeZone.getTimeZone("Asia/Kuala_Lumpur"))` in `@Before` and restore it in `@After`. A helper `ms("2026-11-19 09:00")` parses local time.

```java

@Test public void dueOnTheNextThursday() {
```
