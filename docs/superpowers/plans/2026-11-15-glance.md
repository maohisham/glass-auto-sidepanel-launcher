# Glance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Sun theme, a rain heads-up in the weather line, a start-of-drive summary card, and a log-only test of Google Maps and Waze navigation notifications.

**Architecture:** As before, pure rule classes are tested with JUnit, and thin Android code wraps them. Sun reads the last known Syuruk and Maghrib saved in Settings, so every screen (panel, Settings, bubbles, wizard) agrees. The rain line and the summary take what they need from the forecast, prayer data and drive log already in `PanelActivity`. The notification test lives in the existing `MediaListener`.

**Tech Stack:** Android Java, minSdk 31, targetSdk 33, JUnit 4. Build and test from the repo root with:
`JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ./gradlew :headunit:testDebugUnitTest :headunit:assembleDebug -q`

**Spec:** `docs/superpowers/specs/2026-11-15-glance-design.md`

## Global Constraints

- Nothing new that stays on the panel and needs a tap to clear.
- The panel reads notifications only from `com.google.android.apps.maps` and `com.waze`. Every other package returns before its notification is read.
- The theme choices are Unit, Light, Dark and Sun (0–3). Existing values keep their meaning, and Sun is never the default.
- Rain counts when an hour has a chance of 60% or more, or a rain or storm weather code:
  - rain codes are 51–67 and 80–82;
  - storm codes are 95, 96 and 99.
- The summary lasts 10 seconds and closes on a tap. Its setting is on by default.
- The navigation log writes at most once every 30 seconds per app, and only when the text changed.
- Every decision is logged with `Spike.log`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Sun around midnight:** dark from Maghrib through midnight until Syuruk, and light after Syuruk.
2. **Sun before prayer times are known:** it follows the unit, and never stays dark all day.
3. **A stale forecast** (fetched three hours ago): the rain check starts from the current hour, not the first hour in the list.
4. **The summary after a recreate** (for example a split resize): it doesn't show again in the same start.
5. **A Maps notification with empty text, or a different app's notification:** nothing is logged and nothing crashes.

### Task 2: Rain heads-up

**Files:**
- Modify: `Forecast.java` (`Hour` gets `final int hour24`), `ForecastParser.java:57`, `PanelView.java` (`bindWeather`, new `setRainLine`), `PanelActivity.java`
- Create: `RainSoon.java`
- Test: `RainSoonTest.java`

**Interfaces:**
- Produces:
  - `Forecast.Hour(String label, int hour24, float tempC, int code, int rainPct)`
  - `RainSoon.isRain(int code)`, `RainSoon.isStorm(int code)`
  - `RainSoon.firstWet(List<Forecast.Hour> hours, int nowHour, int withinHours) -> int`. It returns the index of the first wet hour among the hours starting at `nowHour`, or -1. Hours before `nowHour` at the head of the list are skipped. If `nowHour` isn't in the list, it returns -1.
  - `RainSoon.line(List<Forecast.Hour> hours, int nowHour, int currentCode) -> String`. It returns null when nothing is coming, or when it's raining now (`isRain || isStorm` of `currentCode`). Otherwise it returns `"🌧 Rain likely from " + label` or `"⛈ Storms likely from " + label`, looking within 2 hours.
  - `PanelView.setRainLine(String line)`: when the line isn't null, `bindWeather` passes it to `WeatherLine.build` in place of `weather.city`.
